# 06. 8D 조사 에이전트와 하네스

- 마감: 미정
- 단계: phase-2
- 관련 설계: 설계서 11장(QE 흐름)
- 배경: E6

## 배경

고정 파이프라인은 정해진 순서로만 조사한다. E6에서 원인이 설비 단위이거나 둘이거나 없을 때, 고정 순서로는 풀리지 않는 경우를 확인한다. 실제 QE는 첫 분석 결과를 보고 다음 확인을 고른다. 이 판단을 LLM 에이전트가 하게 하고, 그 판단이 믿을 만한지를 정답으로 채점한다.

에이전트는 계산하지 않는다. 통계 계산은 지금의 분석 함수가 도구로 맡고, 에이전트는 어느 도구를 어떤 인자로 부를지와 결과를 어떻게 서술할지를 맡는다. 에이전트가 잘못된 원인을 지목하거나 숫자를 지어내지 못하게 막는 장치(하네스)가 이 스펙의 핵심이다.

## 목표

8D 흐름(D2 문제 기술 → D3 임시 격리 → D4 원인 조사 → 보고서)을 LangGraph로 구성한 조사 에이전트를 만든다. 하네스와 과거 사례 검색이 원인 특정, 격리, 서술의 정확도를 얼마나 바꾸는지 평가 시드에서 비교한다.

## 범위

### A. 도구 계층

분석 함수를 에이전트가 부를 수 있는 도구로 감싼다. 도구 계층은 LangGraph에 의존하지 않는 순수 파이썬 함수로 두고, MCP 서버로도 노출한다.

| 도구 | 하는 일 |
| --- | --- |
| `monitor` | 공장 전체 관리도와 챔버 감시 알림 |
| `commonality` | 구간과 패턴으로 공통성 분석. 단위(챔버, 설비)와 제외할 웨이퍼를 고를 수 있다 |
| `exposure` | 원인 후보의 노출 기간 추정 |
| `contain` | 노출 기간과 여유 시간으로 보류 로트 목록 |
| `trace_lot` | 로트 하나의 공정 이력 |
| `search_cases` | 과거 조사 기록 검색 (C) |

- 도구 출력에는 결과 ID를 붙인다. 보고서의 주장은 이 ID를 인용해야 한다.

### B. 그래프와 하네스

- 노드: D2 문제 기술, D3 임시 격리 제안, D3 승인(사람 확인으로 멈춤), D4 조사 반복, 보고서 작성, 검증.
- D4는 에이전트가 도구를 골라 반복한다. 도구 호출 수에 상한을 둔다.
- 하네스:
  - 원인 주장은 q < 0.05인 공통성 분석 결과 ID를 인용해야 한다. 인용이 없으면 "원인 미확정"으로 쓴다.
  - 검증 노드는 보고서의 숫자(lift, q-value, 로트 수, 날짜)를 인용한 도구 출력과 대조한다. 어긋나면 보고서를 되돌려 다시 쓰게 한다.
  - 모든 도구 호출과 LLM 호출을 추적 기록으로 남긴다.
- LLM 호출은 기록 후 재생(record and replay)할 수 있게 한다. CI는 API를 부르지 않고 기록으로 돈다.

### C. 과거 사례 검색

- 개발 시드(200~209)로 만든 조사 기록(시나리오, 첫 분석 결과의 특징, 최종 원인 단위, 다음 행동)을 사례로 쌓는다.
- 새 조사의 첫 분석 결과와 비슷한 사례를 찾아 에이전트의 맥락에 넣는다. 예: "1위가 압도적이지 않고 같은 설비의 챔버가 함께 유의했던 사례는 설비 단위 원인이었다."
- 평가 시드의 기록은 사례에 넣지 않는다.

## 실험

### E7. 조사 에이전트와 하네스의 효과

- 관련 이슈: (이슈 생성 후 기입)
- 스크립트: `scripts/run_e7.py`
- 시나리오와 시드: S1~S5, 평가 시드 300~319 (판정 기준은 실행 전에 이 절에 정한다)

**가설**

1. 하네스 있는 에이전트는 고정 파이프라인보다 원인 집합 recall이 높다. 차이는 S2, S3에서 난다.
2. 하네스 없는 에이전트는 지어낸 숫자나 인용 없는 원인 주장을 낸다. 하네스는 이를 0건으로 줄인다.
3. 하네스는 S5에서 원인을 지목하는 오답을 줄인다.
4. 사례 검색을 켜면 같은 정확도를 더 적은 도구 호출로 낸다.

**방법**

- 조건 네 가지를 같은 가상 팹과 같은 예측에 적용한다. LLM 모델과 온도는 고정하고, 조건마다 같은 호출 상한을 둔다.
- 지표: 원인 집합 precision과 recall, 원인별 lot recall과 추가 보류 정상 로트, 지어낸 숫자 수, 인용 없는 주장 수, 도구 호출 수, 토큰 비용.
- LLM 출력은 매번 달라질 수 있으므로, 조건마다 같은 시드를 3번 반복해 분산을 함께 보고한다.
