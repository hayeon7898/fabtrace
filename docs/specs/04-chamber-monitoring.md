# 04. 챔버 단위 감시와 노출 기간 재추정

- 마감: 2026-11-13
- 단계: phase-1
- 관련 설계: 설계서 7장(평가), 11장(QE 흐름)
- 배경: E3 (`results/experiments/20261111-E3.md`)

## 배경

E3에서 공통성 분석은 감지된 8개 시드 모두에서 원인 챔버를 1위로 찾았지만, 앞뒤 단계에 약점이 있었다.

| 단계 | E3 결과 | 원인 |
| --- | --- | --- |
| 감지 | 8/10 | 공장 전체 웨이퍼로 그린 관리도가 챔버 하나의 이상을 묽게 만든다 |
| 격리 | 로트 recall 평균 0.63, 9/10 시드에서 로트를 놓침 | 노출 기간을 관리도 정점 며칠의 웨이퍼로 정해 실제보다 짧게 잘린다 |

두 약점 모두 챔버를 따로 보면 신호가 뚜렷해진다(원인 챔버 안 불량률 약 40%, 평상시 약 5%).

## 목표

챔버 단위로 보아 감지와 격리를 보완하고, 개발에 쓰지 않은 새 시드에서 기존 방법과 같은 조건으로 비교한다.

## 범위

### A. 원인 챔버 기준 노출 기간 재추정

- 원인 챔버가 특정된 뒤, 그 챔버를 지난 웨이퍼만의 통과 날짜별 예측 불량률을 전체 기간에서 계산한다.
- 이항분포 관리한계로 이상인 날을 찾고, 처음 이상 구간과 겹치는 연속 구간(하루 간격까지 이음)을 노출 기간으로 삼는다.
- 기존 방법의 노출 기간과 합쳐, 기존보다 짧아지지 않게 한다. 겹치는 챔버 이상 구간이 없으면 기존 노출 기간을 쓴다.
- 챔버를 지난 웨이퍼가 없는 날은 판단 근거가 없으므로 간격으로 세지 않는다.
- 여유 시간은 기존처럼 노출 기간 앞뒤에 더한다.

### B. 챔버 단위 감시

- 패턴마다, 챔버마다 통과 날짜별 예측 불량률을 감시한다. 공장 전체 감시는 그대로 두고 함께 쓴다.
- 챔버 26개 x 패턴 8개 x 날짜를 동시에 감시하므로, 한 번 실행에서 기대 오탐이 1건 이하가 되도록 꼬리 확률을 정한다.
  - 꼬리 확률은 오탐 예산 0.5를 감시 점 수(챔버 x 패턴 x 웨이퍼가 있는 날)로 나눈 값이다. 판정은 관리한계 초과 한 점(rule1)만 쓴다.
  - 중심선은 패턴마다 공장 전체 관리도의 중심선을 쓴다. 챔버 자신의 중심선은 드문 패턴에서 0이 되기 쉽다.
  - 오탐은 알림 구간(챔버, 패턴별로 이어진 날들) 단위로 센다.
- 챔버 감시가 이상을 알리면 해당 기간을 팹 아웃 기준 구간으로 바꿔 공통성 분석으로 확인한다. 챔버 감시만으로 원인을 확정하지 않는다.
- 통과 날짜 기준 감시는 웨이퍼가 팹 아웃되어 판정이 나온 뒤에 계산할 수 있다. 실시간 감시가 아니라 사후 집계라는 점을 문서에 남긴다.

## 실험

### E4. 챔버 단위 개선 효과 확인

- 관련 이슈: #37
- 스크립트: `scripts/run_e4.py`
- 시나리오와 시드: S1, 평가 시드 100~109 (0~9는 E3에서 결과를 보고 개선 방향을 정했으므로 제외)

**가설**

1. 개선 방법(A + B)의 감지율이 기존 방법보다 높다.
2. 개선 방법은 감지된 시드에서 로트 recall이 기존 방법보다 높고, 여유 24시간에서 놓치는 로트가 거의 없다.
3. 개선 방법이 추가로 보류하는 정상 로트는 적다. (처음에는 "로트 precision 하락은 작다"였으나, QE가 읽기 쉽게 로트 수로 바꿨다)
4. 챔버 감시를 더해도 잘못 지목한 원인 챔버는 늘지 않는다.

**방법**

- 시드 100~109마다 같은 가상 팹과 같은 예측에 기존 방법과 개선 방법을 모두 적용한다.
- A만 켠 경우, A와 B를 모두 켠 경우를 나눠 각 개선의 효과를 따로 본다.
- E3와 같은 지표(감지, 원인 순위, 격리 precision과 recall, 오탐)를 같은 형식으로 요약한다.

**판정 기준** (실행 전에 정함, `experiment.judge_e4`)

baseline 대 A+B(`exposure+chamber`), 여유 24시간(E5에서 유지)으로 판정한다. A만 켠 결과는 참고로 함께 보인다.

| 가설 | 지지 조건 | 근거 |
| --- | --- | --- |
| 1 | A+B의 감지 시드 수가 baseline보다 많다. 둘 다 10/10이면 판정 불가 | |
| 2 | 감지된 시드의 lot recall 평균이 baseline보다 높고, A+B에서 로트를 놓친 시드가 10개 중 1개 이하 | 업계 원칙은 놓치는 로트 0이지만, E5에서 분류 오차가 없어도 시드당 약 8%(50개 중 4개)는 경계 날 신호 부족으로 놓쳤다. 0개를 기준으로 하면 방법이 설계대로 작동해도 지지될 확률이 약 43%라 운을 재게 된다. 1개 이하면 약 81%다 |
| 3 | 두 방법 모두 감지한 시드에서, A+B가 baseline보다 추가로 보류한 정상 로트가 사건당 평균 3개 이하 | 공개된 업계 표준 수치는 없다. 여유 24시간을 정할 때 원인 챔버를 하루 동안 지난 로트는 정상이어도 보류하기로 했고, `ETCH-03`을 지나는 로트는 하루 약 2.7개(하루 8로트, ETCH 설비 3대)다. 추가 보류가 그 하루치 이내면 이미 받아들인 비용 수준이다. 두 방법 모두 감지한 시드만 보는 이유는, 한쪽만 감지한 시드를 넣으면 비교가 감지율 차이로 바뀌기 때문이다 |
| 4 | 모든 Finding(모든 패턴, 챔버 감시 포함)에서 센 잘못 지목한 원인의 합계가 A+B ≤ baseline | E3의 `false_causes`는 첫 Finding만 세서 챔버 감시가 더한 Finding을 보지 못한다 |

### E5. 개선 방법의 격리 여유 시간 재검토

- 관련 이슈: #41
- 스크립트: `scripts/run_e5.py`
- 시나리오와 시드: S1, 개발 시드 42만. 평가 시드 100~109 결과를 보기 전에 정해야 하므로 E4보다 먼저 실행한다.

**가설**

1. A를 켜면 24시간보다 짧은 여유 시간으로도 lot recall 1.0을 유지할 수 있다.
2. 여유 시간을 줄이면 lot precision이 오른다.

**방법**

- `exposure+chamber` 모드에서 여유 0, 6, 12, 18, 24시간의 lot precision과 recall을 계산한다.
- 실제 예측: seed 42 가상 팹과 `cnn_v1` 예측.
- 합성 예측: seed 42 이력에 맵 배정만 시드 0~49로 바꾼다. 평상시 패턴은 WM-811K 클래스 비율, 영향 웨이퍼는 0.4 확률로 Edge-Ring이다.
- 판단 기준(결과를 보기 전에 정함): 실제 예측 lot recall 1.0, 합성 lot recall 평균 0.98 이상, 최솟값 0.9 이상인 값 중 가장 짧은 값. 24시간보다 짧지 않으면 24시간을 유지한다.
- 새 기본값은 개선 방법(`exposure`, `exposure+chamber`)에만 적용하고, baseline은 24시간을 유지한다.
